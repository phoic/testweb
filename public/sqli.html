3보안 분석

● 왜 취약한가

취약한 로그인은 사용자가 입력한 문자열을 SQL 쿼리 문자열에 그대로 이어 붙입니다. 이때 입력값 안에 '(작은따옴표)나 --(주석 기호) 같은 SQL 문법 요소가 포함되어 있으면, 그 값은 더 이상 "데이터"가 아니라 "명령어의 일부"로 해석됩니다.

  • ' OR '1'='1' -- 를 아이디에 넣으면 조건절이 항상 참이 되어 비밀번호 검증이 통째로 무시됩니다.
  • -- 이후의 원래 쿼리(비밀번호 비교)는 주석 처리되어 실행되지 않습니다.

● 어떻게 방어했는가

안전한 로그인은 Prepared Statement(파라미터 바인딩)를 사용합니다. SQL 문장의 구조(? 가 들어갈 자리)를 먼저 데이터베이스에 전달해 확정한 뒤, 사용자 입력은 오직 "값"으로만 그 자리에 채워집니다.

  • 입력값에 '이나 --가 포함되어 있어도 SQL 문법으로 재해석되지 않습니다.
  • 쿼리의 구조와 사용자 데이터가 처음부터 분리되어 있기 때문에 문자열 조합 자체가 불가능합니다.
