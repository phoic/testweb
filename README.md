# SQL Injection 비교 실험

Node.js · Express · better-sqlite3를 사용하는 로컬 로그인 비교 사이트입니다. 문자열 결합과 매개변수 바인딩을 실제 SQLite에서 실행합니다. 공격 문자열을 감지해 결과를 만들어 내는 로직은 없습니다.

## 실행

Node.js 22 또는 24와 npm이 필요합니다. 이 환경에서는 Node.js 24.19.0으로 검증했습니다.

```bash
cd /workspace/testweb
npm ci
npm start
```

서버는 `127.0.0.1:3000`에만 바인딩합니다. 브라우저에서 `http://127.0.0.1:3000`을 열면 비교 화면으로 이동합니다. `PORT`로 포트를 변경할 수 있습니다. 초기 실행 시 `data/lab.db`와 상위 디렉터리를 자동 생성합니다. `LAB_DB_PATH`를 지정하면 별도의 DB 파일을 사용할 수 있습니다. 외부 대상 접속 기능은 없습니다.

가상 계정: `alice / password123`, `bob / test1234`, `carol / letmein00`. 교육용 DB에는 가상 비밀번호를 평문으로 저장하며, 실제 서비스의 계정·암호 저장 방식으로 사용하지 않습니다. 응답의 계정 정보는 `id`, `username`만 선택합니다.

## 사용

1. 예시 버튼으로 값을 채우거나 직접 입력합니다. 예시 버튼은 요청을 보내지 않습니다.
2. ‘두 방식 비교 실행’을 누릅니다. 클라이언트가 입력을 한 번 캡처하고, `POST /api/sqli/compare`가 같은 입력으로 두 인증 경로를 실행합니다.
3. ‘가상 비밀번호·SQL 입력값 표시’를 켜서 실제 SQL, 별도 바인딩 값, 전송한 입력과 오류 메시지를 확인합니다. 숨김 상태에서는 SQL 원문도 숨겨 비밀번호가 SQL 안에 노출되지 않게 합니다. SQL을 변형해 실제 실행문이라고 표시하지 않습니다.
4. 실행 기록의 ‘결과 보기’로 과거 실행을 다시 표시합니다. 기록은 실행 당시 입력·응답을 JSON 복사하고 동결한 값입니다. 현재 입력 수정과 독립적입니다.
5. JSON으로 기록을 내려받습니다. 파일에는 **숨김 설정과 관계없이 가상 비밀번호를 포함한 원본 입력과 전체 응답**이 들어갑니다. 기록은 현재 탭의 메모리에만 있으며 새로고침하면 초기화됩니다.

화면의 입력 조건은 예시 값과의 정확한 일치에 따라 붙이는 설명용 이름입니다. 인증 또는 우회 판정에는 사용하지 않습니다. 각 실행 식별자와 실행 시각은 서버에서 생성하며 시각은 ISO 8601 UTC로 표시합니다. HTTP/네트워크 실패는 DB 오류와 구분하고, 서버 응답을 받지 못한 요청은 DB 실행 기록으로 추가하지 않습니다. 이때 상세 영역의 이전 실행 식별자를 유지해 이전 결과임을 표시합니다.

## 실제 실행 코드와 VS Code 캡처

- `auth/vulnerable.js`: 3–6행에서 SQL 문자열에 입력을 직접 결합합니다. 12행에서 `prepare(query).all(...boundParams)`를 실행하며 바인딩 배열은 비어 있습니다.
- `auth/parameterized.js`: 3–6행에서 고정 SQL의 `?`와 값 배열을 분리합니다. 12행에서 `prepare(query).all(...boundParams)`로 값을 바인딩해 조회합니다.
- `auth/experiment.js`: 두 경로의 공통 로깅, 반환 계정 처리, 행 수 집계, 인증 판단, 별도 분석 조회를 담당합니다.
- `routes/sqli.js`: 공통 비교 API 및 기존 개별 로그인 API를 연결합니다. 모두 위의 실제 인증 파일을 호출합니다.
- `public/sqli.html`, `public/js/sqli.js`, `public/css/sqli.css`: 입력·실행 결과·기록 화면입니다. 화면에 설명용으로 복제한 JavaScript 코드를 표시하지 않습니다.

VS Code에서 두 인증 파일을 열고 한 파일 탭을 우클릭 → **오른쪽으로 분할**을 선택하세요. 파일마다 17행으로 구성되어 있어 같은 줄끼리 비교할 수 있습니다. JavaScript 언어 모드와 기본 문법 강조만으로 읽을 수 있습니다. `code` 명령을 사용할 수 있으면 다음 명령으로 열 수 있습니다.

```bash
code -r auth/vulnerable.js auth/parameterized.js
```

줄 배경 강조가 필요하면 실제 소스를 수정하지 않고 원하는 줄을 선택한 상태로 캡처하세요. 줄 번호 클릭 또는 줄 시작에서 `Shift+↓`로 선택할 수 있습니다. 테마의 선택 영역 배경이 적용됩니다. 편집기 포커스를 옮기면 선택 강조가 약해질 수 있으므로 VS Code 사용자 설정의 `editor.selectionBackground` 및 `editor.inactiveSelectionBackground`를 조절할 수 있습니다. 확장 프로그램은 필요하지 않습니다.

두 구현은 모두 `prepare()`와 `all()`을 사용합니다. **prepare() 사용 자체가 방어인 것은 아닙니다.** 차이는 SQL 구조에 입력을 결합하는지, 고정 SQL에 입력값을 따로 바인딩하는지입니다.

## 결과와 로그의 의미

- 두 경로는 같은 `users` 테이블을 조회하고, `all()`의 반환 행 수가 1개 이상이고 DB 오류가 없으면 인증 성공으로 판단합니다. 상태는 공통으로 `인증 성공`, `인증 실패`, `DB 오류`입니다. 조회 오류 시 계정 배열은 비고 반환 행 수는 0으로 표시되지만, 이는 정상적으로 0행을 조회한 인증 실패와 별개의 오류 상태입니다.
- 비교 API는 한 동기 SQLite 트랜잭션에서 두 경로와 별도 분석 조회를 실행합니다. 입력과 DB 상태를 맞추기 위한 것이며 인증 세션을 생성하지 않습니다.
- 별도 매개변수화 조회로 정확한 계정 일치를 확인합니다. 정확한 일치는 없지만 취약 경로가 인증에 성공했을 때만 `인증 우회 관찰`로 표시합니다. 이 조회는 원래 인증 결과를 바꾸지 않습니다. 분석 조회 자체가 실패하면 우회 여부는 `null`(판정 불가)이며 오류를 표시합니다.
- 로그는 서버 처리 지점에서 `request_received`, `sql_ready`, `db_completed` 또는 `db_error`, `rows_counted`, `auth_decided` 순서로 생성됩니다. `sql_ready`는 사용할 SQL과 값의 **구성이 완료된 시점**이며 SQLite의 `prepare()`가 성공했다는 뜻은 아닙니다. 오류는 prepare 또는 all 호출에서 발생할 수 있습니다. 각 로그에 실행 식별자·시각·인증 경로가 있습니다.
- 로그는 서버 애플리케이션의 처리 기록이며 SQLite 내부 추적 자료가 아닙니다. 화면 하단의 원리 설명은 실행 로그와 분리했습니다. 처리 시간이나 애니메이션 기반 시간 측정은 없습니다.
- 방어 경로는 실제 SQL 템플릿과 바인딩 배열을 별도로 반환합니다. 값이 대입된 SQL 문자열을 만들어 실제 실행문으로 제시하지 않습니다.

기존 XSS 실습 파일은 이 변경 범위에서 보존했지만 서버에서 XSS API를 등록하지 않으며, 첫 화면의 대시보드와 XSS 이동 링크는 제거했습니다.

## 검증

```bash
npm test
```

Node.js 기본 테스트 러너가 임시 SQLite 파일과 실제 HTTP 서버를 사용합니다. 정상 계정, 잘못된 비밀번호, 논리식·주석 예시, 작은따옴표 오류, 키워드만으로 우회를 판정하지 않는 동작, 방어 경로·분석 조회의 실제 DB 오류, 실행 식별자, 입력 검증을 확인합니다. 임시 DB는 테스트 후 정리합니다.

브라우저 검증에는 Python Playwright와 로컬 Chromium이 필요합니다. 이 환경에 설치된 도구를 사용했습니다. 별도 환경에서 실행하려면 먼저 해당 도구를 설치하고, 필요하면 `test/browser.py`의 Chromium 실행 파일 경로를 변경하세요.

```bash
python3 test/browser.py
```

실제 Chromium으로 예시 버튼, 정상/오류/우회 비교, 같은 입력 전달, 중복 제출 방지, 실행 중 입력 변경, 과거 기록 보존, JSON 다운로드, 표시·숨김, 네트워크 오류, 모바일 가로 넘침을 확인합니다. 검증은 임시 DB와 별도 포트를 사용하며 브라우저와 서버를 종료합니다. 화면 캡처는 `/tmp/testweb-comparison.png`에 저장합니다.
